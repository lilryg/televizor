# Телевизор

Веб-кинозал на 2–10 участников. Никнейм хранится в браузере, личность участника подтверждается анонимной сессией Supabase. На GitHub Pages размещаются статические файлы приложения. Для входа в комнату нужна ссылка-приглашение, а после входа настоящий доступ к комнате проверяет база данных.

## Подключение и публикация

1. Открой [настройки входа в Supabase](https://supabase.com/dashboard/project/_/auth/providers), выбери свой проект и включи **Allow anonymous sign-ins**. Если разворачиваешь новую базу, открой **SQL Editor → New query** и запусти `supabase/migrations/20261120000000_televizor.sql` один раз. В проекте `kheqewkvhlbsmwipiwcd` миграция уже применена.
2. В Supabase открой **Connect** и скопируй **Project URL** и **Publishable key**. Ключ начинается с `sb_publishable_`. Он предназначен для браузера. Держи ключи `service_role` и `sb_secret_` вне проекта и GitHub.
3. На GitHub создай пустой публичный репозиторий `televizor`. На бесплатном GitHub Pages репозиторий и страница доступны по обычной ссылке, а доступ к комнатам защищает Supabase. Загрузи файлы проекта в ветку `main`, включая скрытую папку `.github` и без файла `.env.local`.
4. Открой **Settings → Secrets and variables → Actions → Variables**. Добавь переменные **VITE_SUPABASE_URL** и **VITE_SUPABASE_KEY** со скопированными значениями.
5. Открой **Settings → Pages**. В **Build and deployment → Source** выбери **GitHub Actions**.
6. На вкладке **Actions** выбери **Build and deploy GitHub Pages → Run workflow**. Когда обе задачи станут зелёными, открой ссылку из **Settings → Pages**. Ссылки на комнаты используют хеш вида `#room=…`, поэтому обновление страницы остаётся на той же точке входа GitHub Pages.

## Проверка на компьютере

Установи Node.js 24. В папке проекта выполни `npm install`, затем `npm run dev`. Для другого проекта скопируй `.env.example` в `.env.local` и укажи его URL и публичный ключ.

- `npm test` проверяет никнеймы, ссылки, расчёт позиции и статус присутствия.
- `npm run build` проверяет типы и собирает сайт в `dist/`.
- `tests/rooms.sql` можно запустить из SQL Editor. Он проверяет права от имени разных участников и откатывает тестовые данные.

Для сквозной проверки открой сайт в обычном окне и в приватном окне. Создай комнату, скопируй приглашение, войди под вторым никнеймом. Проверь обновление страницы, передачу роли хоста и удаление участника. Добавь доступную прямую HTTPS-ссылку, проверь Play, Pause и перемотку из обоих окон. Отключи сеть на одном устройстве и включи снова. Для видео и звука вкладки используй Chrome или Edge на компьютере, выбери именно вкладку и включи передачу её звука. Открой приглашение на телефоне и проверь просмотр и разворот.

## Как работает трансляция

Хост передаёт изображение и звук напрямую каждому зрителю. Для 1080p на большой компании нужен запас исходящей скорости у хоста. В сложных сетях может потребоваться TURN. Для его настройки укажи массив объектов RTCIceServer в переменной `VITE_ICE_SERVERS`. Любые значения в этой переменной видны браузеру. Для TURN с ограниченным доступом нужен отдельный механизм выдачи временных учётных данных.

Хост управляет сторонним плеером с выбранной вкладки. Расширение для Play/Pause/Seek на сторонних сайтах выделено в следующий этап. Во встроенном плеере эти действия доступны всем участникам.

Комната рассчитана на 10 одновременных участников. При потере связи у хоста его роль переходит к одному из активных участников примерно через 95 секунд, а захват прекращается. Комнаты без активности удаляются через сутки.
